## Map
- **SubscriptionManager**: no owner, no proxy, no pause, no admin. Merchants call createPlan (immutable price). Subscribers call subscribe / subscribeWithPermit2 (only msg.sender can subscribe themselves). charge() is permissionless and pulls USDC via transferFrom, falling back to Permit2. It splits 99/1 to the merchant and FeeRouter. Subscriber or merchant can pause, resume and cancel. Only the subscriber can call changePlan (same merchant only, with prorated credit).
- **FeeRouter**: permissionless sweep() to the treasury. Only the treasury can call setTreasury.
- **Keeper**: indexes events into SQLite, calls charge() using a hot key (LEVY_KEEPER_KEY in env, set by ops/set-keeper-key.sh), and sends Ed25519-signed webhooks.
- **API**: SIWE login, 24h sessions stored as SHA-256 hashes, `__Host-` HttpOnly SameSite=Strict cookie with an Origin check on writes. Routes are scoped per address. Webhook URL checks run on every DNS resolution (IPv4 blocklist, IPv6 global-unicast allowlist, https on port 443 only, no redirects).

## Findings
Severity counts: Critical 0, High 0, Medium 2, Low 4, Info 5.

### M-1 Merchant can resume a subscription the subscriber paused (also auto-paused ones)
- File: src/SubscriptionManager.sol:334-343 (resumeSubscription uses _onlySubscriberOrMerchant, L404-410). This is documented in SPEC.md:28/32.
- Impact: a subscriber's pause does not stop billing on its own. The merchant can resume at any time, after which charge() pulls immediately against the subscriber's remaining allowance. The same applies after an auto-pause: the merchant resets failedAttempts and restarts dunning.
- Exploit sketch: the subscriber pauses to stop paying. The merchant calls resumeSubscription, sets nextChargeAt = now, and the keeper (or anyone) charges right away.
- Fix: record who paused. A subscriber pause should be resumable only by the subscriber. A merchant may resume only its own pause, and possibly an auto-pause, but only with subscriber consent.

### M-2 Back-billing of all missed cycles in a burst after a PAST_DUE recovery
- File: src/SubscriptionManager.sol:248 (`nextChargeAt += cycleSeconds` from the old value) together with L239.
- Impact: after a run of failures, nextChargeAt stays in the past. Once the subscriber's balance or allowance comes back, anyone can call charge() repeatedly in one block and pull every missed cycle back-to-back. The auto-pause is reached only after 1+3+7·(2m−3) days of recorded failures, so with a 1-day cycle and maxFailed=10 that is up to ~120 cycles. Resume forgives overdue cycles, but recovery from PAST_DUE does not. This is reasoning from the code and has not been run as a PoC (**unverified by test**).
- Exploit sketch: a daily $5 plan fails for 30 days. The subscriber tops up $200 to pay one cycle, and a bot calls charge() 30 times and pulls $150.
- Fix: on a successful charge out of PAST_DUE, set nextChargeAt = max(old+cycle, now+cycle) (or charge at most one overdue cycle), matching the resume semantics. Add a test.

### L-1 A blacklisted or reverting merchant or FeeRouter hard-reverts charge()
- File: L269-270 (safeTransfer happens after the pull, outside the try).
- Impact: if Circle blacklists a merchant, charge() reverts with no failure recorded, so the subscription stays "chargeable" forever and the keeper keeps spending gas on it. If the FeeRouter address is ever blacklisted, every charge across the protocol reverts. With no admin and immutable contracts, the only remedy is to redeploy.
- Fix: have the keeper skip subscriptions that repeatedly revert. Optionally hold the merchant share for withdrawal (pull pattern) instead of pushing it.

### L-2 subscribeWithPermit2 can be griefed by front-running the permit
- File: L192. Anyone can submit the signed PermitSingle directly to Permit2 first, which uses the nonce, so the subscriber's transaction reverts.
- Impact: DoS only. The allowance does get set, so the user can retry with subscribe(). No funds are lost.
- Fix: wrap permit2.permit in try/catch and proceed if the allowance is already sufficient (the standard pattern).

### L-3 FeeRouter.setTreasury is a single step
- File: src/FeeRouter.sol:39-44. A typo permanently redirects all future fees, and it cannot be recovered because only the new treasury can change it. Deploy.s.sol checks for a contract treasury on mainnet only at deploy time.
- Fix: use a two-step propose/accept flow, or require code at the new address.

### L-4 One allowance is shared across all of a subscriber's subscriptions
- File: L283-293. The ERC-20 approve and Permit2 allowance belong to the subscriber and are not tied to a subscription, so there is no per-subscription cap. Over-pulling is bounded by plan price × elapsed cycles (plus M-2), and only plans the subscriber joined themselves can pull. A large infinite approval from the UI still magnifies M-1 and M-2.
- Fix: the UI/checkout should approve a bounded amount (e.g. N cycles), and Permit2 expirations should be set. Optionally add per-subscription spend caps on-chain.

### Info
- I-1 No admin keys, proxy, oracle or upgrade path in the contracts, so there is no admin rug or upgrade risk. Off-chain trust sits with the keeper hot key, which can only call permissionless charge() and cannot redirect funds, and with the webhook Ed25519 key (location: keeper/webhook-signing-key.pem path, or the LEVY_WEBHOOK_KEY env var). Compromising it allows forged webhooks to merchants.
- I-2 Fee is `due/100`, rounded down. Plans priced under 100 base units ($0.0001) pay no fee, which is harmless. Proration credit rounds down in the merchant's favour (L380).
- I-3 charge timing: block.timestamp is used with day-scale cycles, so validator skew is negligible. MIN_CYCLE is 1 day, and retry gaps are enforced on-chain to stop a permissionless griefer from forcing auto-pause. Forcing a failure via a low-gas call is not practical because of the 63/64 rule; this reasoning is not tested.
- I-4 Decimals: Deploy checks decimals==6 and pins canonical USDC and Permit2 on chain 5042. Fee-on-transfer and non-standard returns are not relevant to canonical USDC.
- I-5 API: requireSession is applied per route, other users' subscriptions return 404, SIWE nonces come from crypto, and challenges are single-use with a 5-minute TTL and a cap. No SQL string building was spotted in the reviewed paths, though db.ts (686 lines) was not reviewed line by line. Update fastify deps for the fast-uri advisories.

## Mainnet go / no-go
**Conditional GO after M-1 and M-2 are fixed and tested.** The contracts are small and immutable, have no admin, and pass 58 tests plus invariants and Slither. However, the two Medium findings let a merchant bill against a subscriber's wishes or pull many cycles at once, which is a consumer-harm and reputational risk for a payments product. Before launch, also run the Node tests on Node ≥22.5 and fix the fast-uri advisories.

## Fix brief for Claude
In SubscriptionManager, store who initiated each pause: subscriber, merchant, or auto. Only the subscriber may resume a subscriber pause. The merchant may resume its own pause. For an auto-pause, decide on a policy (preferably subscriber-only). Update SPEC.md, the wiki and the dashboard to match, and add tests that a merchant cannot resume a subscriber pause. In charge(), when a successful charge follows one or more failures (status PAST_DUE, or failedAttempts > 0), set the next charge date to the later of the old date plus one cycle and now plus one cycle, so overdue cycles are forgiven the same way resume forgives them. Add a test that topping up after N missed cycles allows exactly one pull per block, and an invariant that total pulled per subscription never exceeds price × (cycles actually started since subscribe, minus forgiven ones). In subscribeWithPermit2, wrap the permit call in try/catch and continue if the existing Permit2 allowance already covers the first cycle. Make FeeRouter.setTreasury two-step (pending treasury plus accept). Have the keeper back off on subscriptions whose charge() reverts outright, such as a blacklisted merchant. Have the checkout approve a bounded amount and set a Permit2 expiry instead of unlimited. Bump fastify dependencies to clear the fast-uri advisories, and pin CI to Node ≥22.5 so the sqlite-backed tests run.
